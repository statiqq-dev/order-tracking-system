# Система учета заказов

Консольное приложение для менеджеров и операторов: учет клиентов,
товаров в заказах и готовности заказов к выдаче. В рамках ПР3 основные
сущности проекта представлены классами и связаны в объектную модель.

## Возможности

- Просмотр и добавление клиентов, поиск по имени без учета регистра.
- Удаление клиента, если у него нет заказов.
- Просмотр, добавление, изменение и поиск товаров.
- Удаление товара, если он не используется в заказах.
- Создание заказа для существующих клиента и товара; проверка количества.
- Просмотр заказов с именем клиента, стоимостью и текстовым статусом.
- Поиск по клиенту и подстроке названия товара.
- Изменение статуса: в обработке / готов к выдаче.
- Удаление (отмена) заказа.
- Фильтрация по статусу; сортировка по сумме, товару или ID в обе стороны.
- Статистика: количество заказов, готовые и обрабатываемые заказы,
  число клиентов с заказами, общая сумма.
- Загрузка JSON при запуске, сохранение после каждого изменения.

## Запуск

Требуется Python 3.10 или новее. Код приложения использует стандартную
библиотеку; pytest и flake8 нужны для разработки.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

## Структура проекта

- `main.py` — меню, вывод, обработка ошибок, сохранение изменений.
- `clients.py` — класс `Client` и операции с коллекцией клиентов.
- `products.py` — класс `Product` и операции с коллекцией товаров.
- `orders.py` — класс `Order`, поиск, генератор фильтрации, сортировка
  и статистика заказов.
- `storage.py` — преобразование JSON в объекты и объектов в JSON.
- `utils.py` — ввод чисел и генерация идентификаторов.
- `data/clients.json`, `data/products.json`, `data/orders.json` — данные приложения.
- `tests/test_project.py` — автоматизированные проверки объектной модели.
- `requirements.txt` — инструменты тестирования и проверки оформления.
- `pytest.ini` — пути импорта и каталог тестов.

## Объектная модель

### Client

Клиент хранит `id`, `name` и `phone`. Конструктор проверяет имя и телефон,
`from_data()` создает объект из данных JSON, а `__str__()` формирует строку
для вывода в консоль.

### Product

Товар хранит `id`, `name` и `price`. Метод `update()` изменяет название и цену,
`from_data()` создает объект из данных JSON, а `__str__()` используется для
вывода товара.

### Order

Заказ хранит `id`, объекты `Client` и `Product`, количество `quantity` и
признак готовности `is_ready`. Основные методы:

- `calculate_total()` — рассчитывает стоимость заказа;
- `change_status()` — изменяет готовность заказа;
- `get_status()` — возвращает текстовый статус;
- `from_data()` — восстанавливает заказ из JSON и связанных объектов;
- `__str__()` — формирует полную информацию о заказе.

`Order` связан с конкретными объектами клиента и товара. Поэтому имя клиента,
название товара и цена доступны через `order.client` и `order.product` без
дополнительного поиска по идентификаторам. Функции поиска, фильтрации,
сортировки и статистики работают с коллекциями объектов и остаются обычными
функциями.

## Формат данных и ограничения

Каждый JSON-файл содержит список словарей. Пример одного клиента:

```json
{"id": 1, "name": "Иван Иванов", "phone": "2234562"}
```

Пример товара:

```json
{"id": 1, "name": "Клавиатура", "price": 3500.0}
```

Пример заказа:

```json
{
  "id": 1,
  "client_id": 1,
  "product_id": 1,
  "quantity": 2,
  "is_ready": false
}
```

JSON используется только как формат хранения. При загрузке записи преобразуются
в `Client`, `Product` и `Order`, причем для каждого заказа восстанавливаются
ссылки на существующие объекты клиента и товара. Если связанный объект не найден,
загрузка прекращается с сообщением об ошибке.

При сохранении ссылки `order.client` и `order.product` преобразуются обратно
в `client_id` и `product_id`. После изменения данных и при выборе 0 программа
сохраняет три списка. При ошибке записи изменения
остаются в памяти: выберите 0 для повторной попытки. Ctrl+C завершает работу
без повторного сохранения. Защиты от частичной записи при сбое нет.

Отсутствующий файл означает пустой список. Ошибка чтения JSON останавливает
запуск с сообщением. При ручном редактировании необходимо соблюдать показанный
формат и уникальность ID. Конструкторы проверяют пустые строки, положительные
цену и количество. Целое количество обеспечивает функция `input_int()`.
Изменение цены объекта товара влияет на стоимость связанных заказов.

## Проверки

```sh
python -m pytest
python -m flake8
```

Тесты проверяют создание объектов, их атрибуты и методы, строковое
представление, взаимодействие клиента, товара и заказа, операции над
коллекциями, ограничения удаления и восстановление объектных связей из JSON.
